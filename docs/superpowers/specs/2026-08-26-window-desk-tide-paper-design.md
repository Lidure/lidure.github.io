# 「窗边书桌 × 潮汐纸页」博客全站重设计规格

日期：2026-08-26  
状态：设计已确认，待实施计划  
适用仓库：`Lidure/lidure.github.io`

## 1. 背景与目标

当前博客已经具备完整的个人站功能，包括全屏/横幅壁纸、主题色相、背景外观面板、文章、碎碎念、留言、搜索、标签、播放器、SEKAI 闯关等。但视觉实现经历了多轮叠加，`BaseLayout.astro` 同时加载多代 Firefly 样式文件，页面之间形成了明显的“局部都被设计过，但不像同一个人长期维护出来的站点”的问题。

本次重设计不是再增加一层样式，而是重建全站视觉语言与信息层级，使博客满足以下目标：

1. 保留现有壁纸、主题色相、外观设置等最有辨识度的能力。
2. 将壁纸从“UI 主体”退回为“环境氛围”，让内容本身拥有稳定阅读结构。
3. 首页从博客门户改为“先认识作者，再进入内容”的个人主页。
4. 文章页成为真正适合长文阅读的排版页面，并加入自动 H2/H3 目录。
5. 碎碎念从“动态系统 UI”转为更像真实生活记录的内容流。
6. 公共页面统一视觉语法，避免每页都像独立模板。
7. 清理多代 CSS 覆盖层，形成单一、可维护的设计系统。
8. 明显降低通用 SaaS、玻璃拟态、组件库拼装与“AI 设计稿”气质。

## 2. 设计定位

整站视觉方向定为：**「窗边书桌 × 潮汐纸页」**。

比喻关系：

- 壁纸 = 窗外环境与情绪。
- 主题色 = 墨迹、划线、当前状态与少量强调。
- 首页 = 进入作者房间后看到的桌面入口。
- 文章 = 摊开的纸页。
- 碎碎念 = 便笺、照片与生活切片。
- 归档/标签 = 索引页。
- About = 慢慢认识作者的一页。

视觉比例：**70% 日常小清新 + 30% ACG 个人气质**。二次元感主要通过头像、音乐、游戏、插图、内容语气与少量细节体现，不把每个控件都 ACG 化。

## 3. 设计原则

### 3.1 内容优先

任何组件在去掉背景、阴影、圆角后仍应具有清晰层级。如果必须依赖强渐变、重阴影或大圆角才能成立，应优先重构信息结构，而不是继续装饰。

### 3.2 少卡片化

不再默认“每个模块都是一张卡”。容器只在确实需要分组时出现。文章列表、标签、导航、状态、归档等优先使用排版、线条、留白和位置关系表达层级。

### 3.3 主题色克制

主题色只用于：

- 当前导航状态；
- 链接与细下划线；
- 文章目录当前章节；
- 少量图标、标记、细线；
- hover/focus 状态。

避免让整个页面大面积染色。

### 3.4 壁纸与内容解耦

壁纸继续支持 banner / fullscreen / overlay 等现有模式，但内容层必须在无壁纸状态下也成立。内容颜色从设计 token 获取，不直接根据某张壁纸单独写规则。

### 3.5 有意保留“人排过”的节奏

桌面端允许轻微不对称、图片突破正文宽度、不同类型内容有不同密度；但不使用随机旋转、过量胶带/贴纸、强手账拟物来制造“人工感”。移动端所有装饰性错位归零。

## 4. 字体系统

### 4.1 正文字体

全站普通文本统一采用：

`Zen Maru Gothic` → `PingFang SC` → `Microsoft YaHei` → `sans-serif`

用于：正文、导航、文章列表、标签、碎碎念、留言、公共 UI。

### 4.2 手写字体

`Ma Shan Zheng` 仅用于：

- 站名；
- 极少量签名式短句；
- 必要的手写装饰。

不得用于长正文、表单、导航主体。

### 4.3 等宽字体

代码块、行内代码继续使用现有等宽字体方案，不受本次视觉字体统一影响。

## 5. 信息架构

主导航调整为：

- 首页
- 文章
- 碎碎念
- 归档
- 关于

右侧工具区保留搜索、外观/主题、播放器等常用功能，但视觉弱化。

以下入口不删除，但退出一级主导航：

- 留言
- 标签
- 沉浸播放器
- SEKAI 闯关

它们通过“更多”、About、页脚或页面内链接进入。

### 5.1 页面职责

- `/`：认识作者与最近内容。
- `/posts`：浏览文章。
- `/moments`：浏览最近生活记录。
- `/archive`：按时间查找历史内容。
- `/about`：作者、兴趣、项目、联系方式。
- `/tags`：内容索引工具。
- `/messages`：留言簿。
- `/player`、`/sekai-quest`：保留独立场景体验，只同步全局字体、导航入口和主题基础变量。

## 6. 首页设计

### 6.1 结构

移除当前“三栏门户”首页。首页按以下顺序组织：

1. 个人开场。
2. 最近正在做 / 听 / 玩。
3. 最近写下的东西。
4. 最近的日常。
5. 更多内容入口。

### 6.2 第一屏

第一屏不再使用大型 Featured 卡与功能矩阵。

主要内容：

- 作者名称；
- 一句短描述或当前状态；
- 少量生活状态，例如“最近在研究 / 在听 / 在玩”；
- 一个小视觉焦点，可为头像、近期照片或当前歌曲封面。

状态内容集中放在独立的小配置文件中，未配置的状态项自动隐藏。

### 6.3 文章展示

“最近写下的东西”采用编辑式层级：

- 1 篇主要文章；
- 2–4 篇较轻文章条目；
- 不强制所有文章使用相同卡片尺寸；
- 不使用 `FEATURED`、`RECENT POSTS` 等大写英文栏目标签作为主要视觉。

### 6.4 最近日常

从碎碎念数据中展示 2–3 条最近内容。优先让访问者直接看到文字/照片本身，而不是动态操作控件。

## 7. 文章页设计

### 7.1 文章头部

- 标题左对齐；
- 描述作为轻前言；
- 日期、更新时间、阅读时间、标签组成一行轻量元信息；
- 标签显示为 `#标签` 文本，不做 pill；
- 文章头与正文之间使用留白建立节奏。

### 7.2 自动目录

目录自动读取 Markdown headings：

- H2 = 一级目录；
- H3 = 二级目录，视觉缩进；
- 标题总数少于 2 个时隐藏目录。

桌面端：

- 左侧 sticky 目录；
- 中央正文；
- 目录包含轻量纵向阅读线；
- 当前章节以主题色文字 + 线/点状态高亮；
- 点击平滑滚动；
- 同步 URL hash；
- 滚动时自动更新当前章节；
- 长目录内部可滚动。

移动端：

- 正文前使用可折叠目录；
- 使用原生可访问结构优先，例如 `<details>`；
- 点击章节后跳转并收起；
- 不保留占宽的固定侧栏。

目录应抽离为明确组件或小模块，不继续把所有目录逻辑堆入 `[slug].astro`。

### 7.3 正文排版

建议正文宽度：720–760px。

- 字号约 16–17px；
- 行高约 1.8；
- H2 为章节标题，不做彩色整块背景；
- H3 比 H2 降一级；
- 链接采用细下划线 + 主题色；
- 粗体不额外加底色。

### 7.4 媒体

- 普通图片可保持正文宽度；
- 大横图允许突破到约 900–980px；
- 多图支持自然画廊布局；
- caption 小而安静；
- 不强制所有图片圆角和阴影。

### 7.5 引用、代码、表格

- 引用：细竖线 + 弱化文字，不做大色块；
- 代码：保留等宽字体与清晰对比，不增加 Mac 三色按钮等模板装饰；
- 表格：依靠行线与留白，不做完整大圆角卡片。

### 7.6 文章结束

正文结束后以简单分隔进入评论。上一篇/下一篇或相关文章若后续保留，应使用书末索引式文本而非卡片矩阵。

## 8. 碎碎念设计

碎碎念整体方向：**生活切片墙**。

### 8.1 内容类型

- 纯文字：像随手写下的一段便笺，不强制完整卡片。
- 单图：图片是主体，文字退到旁边或下方。
- 多图：轻量相册，不机械均分所有格子。
- 视频：保留更完整播放器容器。

### 8.2 时间与分类

- 日期仅在分组首条出现轻量日记页眉；
- 分类保留，但采用文字筛选 + 主题色短下划线；
- 现有清晨 / 白昼 / 黄昏 / 深夜印记保留但弱化为氛围信息。

### 8.3 功能层与内容层分离

第一视觉层：正文、照片、时间。

第二视觉层：Reaction、评论、置顶、删除等操作。

操作层在 hover、focus 或点击后增强存在感；移动端不能依赖 hover 才能完成关键操作。

### 8.4 发布入口

默认只显示类似“今天想记点什么？”的轻入口，展开后才出现分类、图片、视频等完整发布控件。Emoji / Reaction picker 默认保持关闭。

### 8.5 业务兼容

不得重写或破坏现有：上传、Reaction、评论、登录、删除、置顶、灯箱、API 交互。

## 9. 公共页面设计

### 9.1 文章列表 `/posts`

只承担文章浏览职责，不再混合 GitHub 项目。

按年份自然排列，例如：

- `2026`
- `08.25  标题`
- 描述与 `#标签`

不使用大时间轴节点和统一卡片。

### 9.2 归档 `/archive`

作为纯索引：年份 + 月日 + 标题。支持快速跳年份。统计数据只作为轻量页首信息。

### 9.3 标签 `/tags`

从 pill 云改为文字索引。数量使用弱化上标或小数字。hover/focus 用主题色线条反馈。

### 9.4 留言 `/messages`

从“两栏后台式表单 + Recent Messages”改为留言簿：

- 顶部一句自然引导；
- 输入区像留言簿第一页；
- 历史留言从下方自然展开；
- 管理登录、删除等能力保留但默认不抢普通访客视觉。

现有表单 ID 与 API hook 必须兼容。

### 9.5 About `/about`

新增 About 页面，作为个人信息中心：

- 我是谁 / 这个小站是什么；
- 最近在做什么；
- 游戏、音乐、动画等兴趣；
- 学习/研究与个人项目；
- 少量精选 GitHub 项目；
- 联系方式；
- 站点小时间线。

GitHub 项目从 `/posts` 迁移到 About。

避免“技能百分比”“技术栈卡片墙”“GitHub 数据仪表盘”。

### 9.6 页脚

页脚主体改为个人站语气，例如站名、年份和一句短句。RSS / GitHub / 留言 / 返回顶部等作为低调链接。Astro 与 GitHub Pages 技术信息允许保留，但不作为主体。

## 10. 视觉架构

最终样式按职责收敛，目标文件结构：

```text
src/styles/
  tokens.css
  site-shell.css
  home.css
  article.css
  moments.css
  pages.css
```

特殊体验页可继续维护自己的 CSS。

### 10.1 Tokens

至少包含：

- `--font-body`
- `--font-hand`
- `--font-mono`
- `--ink`
- `--muted`
- `--paper`
- `--paper-soft`
- `--line`
- `--accent`
- `--accent-soft`
- 内容最大宽度
- 正文宽度
- 间距尺度
- 圆角尺度
- 阴影尺度

`--accent` 等主题变量由现有 `--theme-hue` 派生。浅色 / 深色 / 壁纸模式只改变 token 最终值，组件不各自重复计算颜色。

## 11. 与现有主题/壁纸系统的兼容

以下能力必须保留：

- 明暗主题；
- 主题色相；
- 壁纸模式；
- 背景透明度；
- 背景模糊；
- 卡片/纸页透明度相关设置；
- Banner 波纹；
- 减少动画；
- 页面过渡；
- 全屏壁纸相关行为。

本次不重写现有业务逻辑，只让这些设置输出的变量接入新设计 token。

## 12. 样式迁移策略

当前多代 Firefly CSS 不在第一步直接删除。实施阶段顺序：

1. 建立 tokens 与新基础层；
2. 完成导航与首页；
3. 完成文章页；
4. 完成碎碎念；
5. 完成公共页面；
6. 确认新页面不再依赖旧规则后，再移除历史 Firefly 样式层。

最终 `BaseLayout.astro` 不应继续加载 `firefly-refresh`、`firefly-v2`、`firefly-v4`、`firefly-v5`、`firefly-v6` 等多代覆盖文件。

不得创建新的 `v7` 覆盖文件继续压在最上层。

## 13. 代码边界

### 13.1 本次允许修改

- 页面信息层级与模板结构；
- 新的视觉样式体系；
- 文章目录相关交互；
- 导航交互表现；
- 小型配置文件；
- About 页面；
- 为视觉重构所需的局部辅助组件。

### 13.2 本次非目标

- 重写碎碎念后端/API；
- 更换评论系统；
- 重写播放器；
- 重写壁纸设置存储机制；
- 重构 SEKAI 闯关业务代码；
- 新增 CMS；
- 引入大型前端框架替代现有 Astro 架构。

## 14. 响应式规则

### 桌面端

- 允许文章侧目录；
- 首页允许轻微不对称；
- 图片允许突破正文宽度；
- 工具入口可以存在但视觉弱化。

### 平板

- 减少边栏；
- 页面趋向单列；
- 保持完整操作能力。

### 移动端

- 单列为主；
- 文章目录折叠；
- 所有装饰性错位归零；
- 图片自然满宽；
- 控件满足触摸尺寸；
- 不依赖 hover 完成操作。

## 15. 无障碍与交互底线

- 键盘 focus 状态清晰；
- 当前导航使用 `aria-current`；
- 移动菜单维护正确 `aria-expanded`；
- 文章目录锚点在无 JS 时仍可直接使用；
- 尊重 `prefers-reduced-motion` 与站内减少动画设置；
- 深浅主题保证合理文字对比；
- 不用颜色作为唯一状态提示；
- 图片保留合理 alt；
- 不为了设计制造强制横向滚动。

## 16. 测试策略

实施阶段采用 TDD。

### 16.1 结构测试

验证：

- BaseLayout 最终不再加载多代旧 CSS；
- 字体与 tokens 正确接入；
- 首页关键结构存在；
- About / 文章 / 归档 / 标签 / 留言等路由可构建。

### 16.2 文章目录测试

验证：

- H2/H3 正确生成；
- H3 层级正确；
- 锚点 href 正确；
- 标题不足时隐藏；
- 移动目录存在；
- 当前章节状态与交互选择器稳定。

### 16.3 功能回归测试

保护现有关键 hook：

- 碎碎念 reaction picker 默认隐藏；
- 评论 / 上传 / 置顶相关 DOM/API hook 保留；
- 留言表单 ID 与登录 hook 保留；
- 播放器、主题、壁纸关键 DOM 不被删除。

### 16.4 最终验证

至少执行：

```bash
npm run build
npm run test:site
```

并要求 GitHub Actions 全绿、PR diff 人工审查、合并后 Pages 部署成功。最终还需对真实桌面与移动页面做视觉检查，不能用 CI 代替审美验收。

## 17. 验收标准

重设计完成后，应同时满足：

1. 去掉站名后，各普通页面仍明显属于同一站点。
2. 去掉壁纸后，排版本身仍成立。
3. 减少圆角、阴影、渐变后，内容层级仍清楚。
4. 首页第一眼像个人主页，而不是 Astro 模板门户。
5. 碎碎念第一眼看到的是生活内容，不是操作按钮。
6. 文章页第一视觉焦点是标题与正文，不是 UI 装饰。
7. 主题色调整在全站有一致但克制的反馈。
8. 深色、浅色、banner/fullscreen/overlay 等主要壁纸模式无明显可读性问题。
9. 桌面、平板、移动端均无关键内容遮挡、强制横向滚动或无法操作的控件。
10. 不新增新的版本号 CSS 覆盖链。

## 18. 实施阶段划分

1. **基础层**：字体、tokens、BaseLayout、主题兼容。
2. **导航与首页**：建立新的第一印象和公共节奏。
3. **文章阅读**：正文排版、H2/H3 自动目录、桌面/移动交互。
4. **碎碎念**：生活切片墙视觉重构，业务逻辑保持兼容。
5. **公共页面**：文章列表、归档、标签、留言、About、页脚。
6. **历史样式清理**：移除不再依赖的旧 Firefly 覆盖层，完成全站回归。

## 19. 设计结论

本次重设计的核心不是“让博客更华丽”，而是把已有功能重新放回合理的信息层级，并建立单一、稳定、可维护的视觉语言。

最终期望用户对站点形成的认知是：

- 首页：这是我。
- 文章：这是我认真写下的东西。
- 碎碎念：这是我最近的生活。
- 归档：这是过去留下的记录。
- 关于：如果还想多认识我一点。

壁纸、主题、音乐、标签、搜索、留言、SEKAI 等功能围绕这些核心内容服务，而不再反过来决定整个网站的外观。
