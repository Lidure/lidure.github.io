# 「窗边书桌 × 潮汐纸页」博客全站重设计规格

日期：2026-08-26  
状态：设计已确认，待实施计划  
适用仓库：`Lidure/lidure.github.io`

## 1. 目标

本次不是在现有视觉上继续叠加一层 CSS，而是重建博客的视觉语言与信息层级。目标是：

1. 保留全屏/横幅壁纸、主题色相、背景外观设置、波纹、播放器等已有特色能力。
2. 让壁纸从“UI 主体”退回为“环境氛围”，内容在无壁纸时也能独立成立。
3. 首页从三栏博客门户改为“先认识作者，再进入内容”的个人主页。
4. 文章页成为稳定的长文阅读页，并加入自动 H2/H3 目录。
5. 碎碎念从“动态系统 UI”变为更像真实生活记录的内容流。
6. 统一文章、归档、标签、留言、About 等普通页面的视觉语法。
7. 清理多代 Firefly CSS 覆盖链，形成单一、可维护的设计系统。
8. 降低通用 SaaS、玻璃拟态、组件库拼装和“AI 设计稿”气质。

## 2. 视觉定位

整站方向：**「窗边书桌 × 潮汐纸页」**。

- 壁纸 = 窗外环境与情绪。
- 主题色 = 墨迹、划线、链接、当前状态。
- 首页 = 进入作者房间后看到的桌面入口。
- 文章 = 摊开的纸页。
- 碎碎念 = 便笺、照片与生活切片。
- 归档/标签 = 索引页。
- About = 慢慢认识作者的一页。

视觉比例：**70% 日常小清新 + 30% ACG 个人气质**。ACG 感主要通过头像、音乐、游戏、插图、内容与少量细节体现，而不是把所有控件动漫化。

## 3. 核心设计规则

### 3.1 内容优先

如果一个模块去掉背景、阴影、圆角之后就失去层级，优先调整结构，而不是继续加装饰。

### 3.2 少卡片化

文章列表、标签、导航、状态、归档等优先使用字体、线条、留白和位置关系表达层级，不再默认“一模块一卡片”。

### 3.3 主题色克制

主题色主要用于：当前导航、链接、细下划线、文章目录当前章节、少量图标/标记以及 hover/focus。避免大面积染色。

### 3.4 壁纸与内容解耦

banner / fullscreen / overlay 等现有壁纸模式继续保留。普通页面从 design tokens 获取内容色与纸页色，不针对具体壁纸写独立皮肤。

### 3.5 有“人排过”的节奏，但不做假手账

桌面端允许轻微不对称、图片突破正文、不同内容密度不同；不使用大量随机旋转、胶带、贴纸或强拟物来强行制造“人工感”。移动端装饰性错位归零。

## 4. 字体

- 普通文本：`Zen Maru Gothic`, `PingFang SC`, `Microsoft YaHei`, sans-serif。
- `Ma Shan Zheng`：仅站名、签名式短句和极少装饰。
- 代码：继续使用现有等宽字体。

正文、导航、文章列表、标签、碎碎念、留言等普通 UI 均使用统一正文字体。

## 5. 信息架构

一级主导航：

- 首页
- 文章
- 碎碎念
- 归档
- 关于

搜索、外观/主题、播放器作为右侧弱化工具入口。

留言、标签、沉浸播放器、SEKAI 闯关不删除，但退出一级主导航，通过“更多”、About、页脚或页面内入口访问。

页面职责：

- `/`：认识作者与最近内容。
- `/posts`：浏览文章。
- `/moments`：最近生活记录。
- `/archive`：按时间查找历史内容。
- `/about`：作者、兴趣、项目、联系方式。
- `/tags`：内容索引工具。
- `/messages`：留言簿。
- `/player`、`/sekai-quest`：保留独立场景体验，只同步全局字体、导航入口和主题基础变量。

## 6. 首页

移除当前三栏门户布局，顺序改为：

1. 个人开场。
2. 最近正在做 / 听 / 玩。
3. 最近写下的东西。
4. 最近的日常。
5. 更多内容入口。

第一屏包含作者名称、一句短描述/当前状态、少量“最近在研究/在听/在玩”和一个小视觉焦点（头像、近期照片或当前歌曲封面）。状态集中存放在小型配置文件中，空值自动隐藏。

“最近写下的东西”采用编辑式层级：1 篇主要文章 + 2–4 篇轻文章条目，不强制等尺寸卡片，不以 `FEATURED`、`RECENT POSTS` 等大写英文 kicker 作为主要视觉。

“最近的日常”展示 2–3 条碎碎念，优先直接展示文字/照片内容。

## 7. 文章阅读页

### 7.1 文章头部

- 标题左对齐；
- 描述作为轻前言；
- 日期、更新时间、阅读时间、标签组成轻量元信息；
- 标签显示为 `#标签` 文本，不做 pill；
- 用留白而不是大卡片分隔头部与正文。

### 7.2 自动目录

目录自动读取 Astro render 输出的 headings：

- H2 = 一级目录；
- H3 = 二级目录；
- H2/H3 总数少于 2 个时隐藏。

桌面端：左侧 sticky 目录 + 中央正文。目录有轻量纵向阅读线，当前章节使用主题色文字并辅以线/点标识；点击平滑跳转并同步 URL hash；滚动时自动高亮；目录过长时自身滚动。

移动端：正文前使用可折叠目录，优先原生 `<details>` 等可访问结构；点击章节后跳转并收起，不放固定侧栏。

目录逻辑抽成明确组件/模块，不继续把全部逻辑堆进 `[slug].astro`。无 JavaScript 时普通锚点仍可用。

### 7.3 正文

正文宽度约 720–760px，字号约 16–17px，行高约 1.8。

- H2 作为章节标题，不使用整块彩色背景；
- H3 再降一级；
- 链接为细下划线 + 主题色；
- 粗体不额外加底色。

图片规则：普通图可在正文宽度内，大横图允许突破至约 900–980px，多图可形成自然画廊，caption 保持克制，不强制所有图片有圆角和阴影。

引用：细竖线 + 弱化文字。代码：保留等宽字体和清晰对比，不加 Mac 三色按钮等模板装饰。表格：主要靠行线和留白。

文章结束后使用简单分隔自然进入评论。上一篇/下一篇或相关文章若保留，采用书末索引式文字，不做卡片矩阵。

## 8. 碎碎念 / 日常

整体方向：**生活切片墙**。

- 纯文字：像随手便笺，不强制完整卡片。
- 单图：图片为主体，文字退居旁边或下方。
- 多图：轻相册，不机械均分所有格子。
- 视频：保留完整播放器容器。

日期只在分组首条出现轻量页眉。分类继续保留，但改为文字筛选 + 主题色短下划线。清晨 / 白昼 / 黄昏 / 深夜印记保留但弱化为氛围信息。

内容层优先显示正文、照片、时间；Reaction、评论、置顶、删除等属于第二层，在 hover/focus/点击后增强存在感，移动端不能依赖 hover 才能操作。

发布入口默认只显示类似“今天想记点什么？”的轻入口，展开后才出现分类、图片、视频等完整字段。Emoji / Reaction picker 默认关闭。

不得重写或破坏现有上传、Reaction、评论、登录、删除、置顶、灯箱与 API 交互。

## 9. 公共页面

### `/posts`

只承担文章浏览，不再混合 GitHub 项目。按年份自然排列“月日 + 标题 + 简短描述 + #标签”，不使用大时间轴节点和统一卡片。

### `/archive`

作为纯索引：年份 + 月日 + 标题，可快速跳年份。文章总数等统计只作为页首轻文字。

### `/tags`

从 pill 云改为文字索引，数量以弱化上标/小数字显示，hover/focus 使用主题色线条。

### `/messages`

从“两栏后台式表单 + Recent Messages”改为留言簿。顶部一句自然引导，输入区像留言簿第一页，历史留言在下方自然展开。管理员登录和删除能力保留但视觉退后；现有表单 ID 与 API hook 必须兼容。

### `/about`

新增 About 作为个人信息中心，包含：

- 我是谁 / 这个小站是什么；
- 最近在做什么；
- 游戏、音乐、动画等兴趣；
- 学习/研究与个人项目；
- 少量精选 GitHub 项目；
- 联系方式；
- 站点小时间线。

GitHub 项目从 `/posts` 迁移到 About。避免技能百分比、技术栈卡片墙、GitHub 数据仪表盘。

### 页脚

主体改为个人站语气：站名、年份和一句短句；RSS / GitHub / 留言 / 返回顶部作为低调链接。Astro 与 GitHub Pages 信息可以保留在次要位置。

## 10. 样式架构

目标收敛为：

```text
src/styles/
  tokens.css
  site-shell.css
  home.css
  article.css
  moments.css
  pages.css
```

播放器与 SEKAI 等特殊体验页可继续维护专属样式。

`tokens.css` 至少提供：

- `--font-body`
- `--font-hand`
- `--font-mono`
- `--ink`
- `--muted`
- `--paper`
- `--paper-soft`
- `--line`
- `--accent`
- `--accent-soft`
- 页面/正文最大宽度
- 间距、圆角、阴影尺度

`--accent` 等由现有 `--theme-hue` 派生。浅色、深色、壁纸模式只改变 token 最终值，组件不各自重复计算颜色。

## 11. 现有主题与业务兼容

必须继续支持：

- 明暗主题；
- 主题色相；
- 壁纸模式；
- 背景透明度与模糊；
- 内容透明度相关设置；
- Banner 波纹；
- 减少动画；
- 页面过渡；
- 全屏壁纸行为；
- 播放器；
- 碎碎念和留言现有业务 API。

本次原则是“重做视觉，不重写业务”。

## 12. 数据流与失败降级

### 首页最近文章

继续从 Astro Content Collection 构建时读取。没有文章时首页仍正常渲染，只隐藏文章区或显示简短空状态。

### 首页最近日常

优先复用现有碎碎念数据/API，不新增第二套内容源。若该数据只能运行时取得，则采用渐进增强：静态首页先完整渲染个人开场与文章区，客户端再加载最近日常。请求失败、超时或返回空数据时直接隐藏“最近日常”内容，不阻塞页面、不弹错误框、不导致构建失败。

### About GitHub 项目

继续复用现有 `getGitHubProjects()`/GitHub 项目获取逻辑。获取失败时 About 仍完整渲染个人介绍与兴趣内容，项目区域使用低调空状态或隐藏，不能让 GitHub 网络/API 错误使整个页面构建失败。

### 图片/壁纸

图片缺失或加载失败不得造成文字不可读。普通内容层必须有独立的 paper/ink token 兜底。

## 13. 样式迁移策略

不在第一步直接删除所有历史 Firefly CSS。实施顺序：

1. 建立 tokens 与新基础层；
2. 完成导航与首页；
3. 完成文章页；
4. 完成碎碎念；
5. 完成公共页面；
6. 确认新页面不再依赖旧规则后，再移除历史 Firefly 样式层。

最终 `BaseLayout.astro` 不应继续加载 `firefly-refresh`、`firefly-v2`、`firefly-v4`、`firefly-v5`、`firefly-v6` 等多代覆盖文件，也不得新增 `v7` 一类覆盖层继续压在最上面。

## 14. 代码边界

允许修改：页面信息层级、模板结构、新样式体系、文章目录交互、导航表现、小型状态配置、About 页面以及视觉重构所需的小组件。

非目标：重写碎碎念后端/API、更换评论系统、重写播放器、重写壁纸存储机制、重构 SEKAI 闯关业务、新增 CMS、引入大型前端框架替换 Astro。

## 15. 响应式

桌面：允许文章侧目录、首页轻微不对称、图片突破正文宽度。

平板：减少边栏，趋向单列。

手机：单列为主，目录折叠，装饰性错位归零，图片自然满宽，控件满足触摸尺寸，不依赖 hover。

## 16. 无障碍与体验底线

- 键盘 focus 清晰；
- 当前导航使用 `aria-current`；
- 移动菜单维护正确 `aria-expanded`；
- 目录锚点无 JS 时仍可使用；
- 尊重 `prefers-reduced-motion` 与站内减少动画；
- 深浅主题保证合理文字对比；
- 不以颜色作为唯一状态提示；
- 图片保留合理 alt；
- 不制造强制横向滚动。

## 17. 测试策略

实施采用 TDD。

结构测试：

- BaseLayout 最终不再加载多代旧 CSS；
- 字体与 tokens 正确接入；
- 首页关键结构存在；
- About、文章、归档、标签、留言等路由可构建。

文章目录测试：

- H2/H3 正确生成；
- H3 层级正确；
- href 锚点正确；
- 标题不足时目录隐藏；
- 移动目录存在；
- 当前章节交互选择器稳定。

功能回归：

- 碎碎念 reaction picker 默认隐藏；
- 评论、上传、置顶相关 hook 保留；
- 留言表单 ID 与登录 hook 保留；
- 播放器、主题、壁纸关键 DOM 不被删除。

最终至少执行：

```bash
npm run build
npm run test:site
```

同时要求 GitHub Actions 全绿、PR diff 人工审查、合并后 Pages 部署成功，并对真实桌面/移动页面做视觉检查。CI 不能替代审美验收。

## 18. 验收标准

1. 去掉站名后，各普通页面仍明显属于同一网站。
2. 去掉壁纸后，排版本身仍成立。
3. 减少圆角、阴影、渐变后，内容层级仍清楚。
4. 首页第一眼像个人主页，而不是 Astro 模板门户。
5. 碎碎念第一眼看到生活内容，而不是操作按钮。
6. 文章页第一视觉焦点是标题与正文，而不是 UI 装饰。
7. 主题色调整在全站有一致但克制的反馈。
8. 深色、浅色、banner/fullscreen/overlay 等主要模式无明显可读性问题。
9. 桌面、平板、移动端无关键内容遮挡、强制横向滚动或无法操作的控件。
10. 不新增版本号 CSS 覆盖链。

## 19. 实施阶段

1. 基础层：字体、tokens、BaseLayout、主题兼容。
2. 导航与首页：建立新第一印象和公共节奏。
3. 文章阅读：正文排版、H2/H3 自动目录、桌面/移动交互。
4. 碎碎念：生活切片墙视觉重构，业务逻辑保持兼容。
5. 公共页面：文章列表、归档、标签、留言、About、页脚。
6. 历史样式清理：移除不再依赖的旧 Firefly 覆盖层并完成全站回归。

## 20. 结论

本次重设计的重点不是让博客更华丽，而是把已有功能放回合理的信息层级，并建立一套稳定、个人化、长期可维护的视觉语言。

最终认知应当是：

- 首页：这是我。
- 文章：这是我认真写下的东西。
- 碎碎念：这是我最近的生活。
- 归档：这是过去留下的记录。
- 关于：如果还想多认识我一点。

壁纸、主题、音乐、标签、搜索、留言、SEKAI 等功能围绕核心内容服务，而不再反过来决定整个网站的外观。
