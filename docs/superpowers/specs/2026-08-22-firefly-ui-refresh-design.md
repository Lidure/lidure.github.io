# Firefly 风格 UI 改造设计

日期：2026-08-22

## 1. 背景与目标

当前站点已经形成了明显的二次元、Project SEKAI、视频背景与音乐交互特色，但普通博客页面的视觉语言同时叠加了多层渐变、毛玻璃、发光、胶囊按钮、漂浮装饰和持续动画，容易呈现出常见 AI 生成 Landing Page 的观感。

本次改造不迁移 Firefly 主题，也不直接复制其组件实现，而是借鉴 Firefly 的信息层级、Banner 与内容分区、文章卡片、侧栏和克制的主题变量体系，在保留现有功能与内容结构的前提下重做普通博客页面视觉。

目标：

- 普通博客页面明显减少“AI UI / 玻璃拟态 Landing Page”观感。
- 首页和普通内容页向 Firefly 的清爽博客结构靠拢。
- 保留站点自己的视频背景、Project SEKAI、音乐播放器、碎碎念等特色功能。
- 沉浸页面继续使用全屏视频背景，不受普通博客布局约束。
- 桌面、平板、移动端均保持合理的信息层级和可读性。
- 不为了视觉改造引入不必要的新依赖或大规模重构内容模型。

## 2. 设计原则

### 2.1 内容优先

视频和图片负责氛围，正文区域负责信息。普通页面不再让每张卡片同时承担渐变、透明、模糊和发光效果。

### 2.2 一套主视觉语言

普通页面统一使用：页面底色、卡片底色、主题色、主文字、次级文字、分隔线。辅助颜色只在少量状态或个性化元素中使用。

### 2.3 保留站点辨识度

不把网站改成 Firefly 换皮。保留现有内容、音乐、Project SEKAI 氛围和视频资产，只借鉴 Firefly 的布局与视觉秩序。

### 2.4 普通页与沉浸页分离

站点明确存在两套页面模式：

- 普通博客模式：Banner + 内容区，克制、清爽、可读。
- 沉浸模式：全屏视频背景 + 现有沉浸交互，可继续使用透明与模糊浮层。

## 3. 页面架构

### 3.1 普通首页与普通内容页

采用 B3 布局：

- 桌面端 Banner 高度约 50vh。
- 移动端 Banner 高度约 36vh，可在约 34–38vh 范围根据视觉效果调整。
- Banner 以下进入独立内容区域。
- 主内容容器向上覆盖 Banner 底边约 24–32px，形成轻微层叠关系。
- 页面主体宽度控制在约 1100–1180px。

普通首页主体采用双栏：

- 左侧文章主栏：约 68–72%。
- 右侧个人侧栏：约 28–32%。
- 栏间距约 20–24px。

平板适当压缩侧栏；移动端改为单栏，并按“简洁个人卡 → 最新文章”的顺序展示。

### 3.2 沉浸页面

沉浸页继续保留 100vh 全屏视频背景。

- 不套普通页 Banner。
- 不套普通页实色页面背景。
- 原有沉浸交互和视频表现继续保留。
- 导航可隐藏或使用极简透明浮层。
- 毛玻璃、半透明和 overlay 在这里作为允许的视觉例外。

## 4. 导航栏

导航改为结构化 sticky navbar，不再使用独立的大胶囊悬浮卡。

### 4.1 Banner 顶部状态

- 位于 Banner 顶部时背景基本透明。
- 保留轻微文字阴影或必要的对比增强。
- blur 很弱或不启用。
- 不使用大面积边框、厚阴影或渐变底色。

### 4.2 滚动状态

页面向下滚动后：

- 导航变为半透明实底。
- 推荐透明度约 0.82–0.90。
- backdrop blur 约 14–18px。
- 可使用极淡底边或轻阴影区分页面内容。

### 4.3 导航内容

主要入口直接作为文字菜单展示，例如：首页、文章、碎碎念、音乐、关于。

搜索、主题切换、更多功能放在右侧图标区。

当前页面状态只使用主题色文字、浅底色或短下划线，不使用渐变胶囊高亮。

## 5. Banner

普通页 Banner 保留现有视频背景能力。

### 5.1 视频

- 自动播放、静音、循环逻辑继续保留。
- 桌面约 50vh。
- 移动端约 36vh。
- 保持 object-fit: cover 风格。

### 5.2 遮罩

视频上只覆盖用于保证文字可读性的克制遮罩。

- 暗场参考 rgba(0, 0, 0, 0.22–0.30)。
- 亮色视频根据实际素材适当降低遮罩。
- 不再在 Banner 上叠多层彩色 radial glow。

### 5.3 文案

Banner 只保留：

- 主标题，例如“搁浅的小窝”。
- 一行副标题、随机短句或当前心情。

删除普通首页 Hero 中类似 `Sweet Blog Corner` 的 kicker 和三个 floating shape。

主标题以干净的中文无衬线或较轻个性字体为主，桌面推荐约 2.4–3rem，不再使用过度夸张的 3.8rem 手写展示风作为普通首页核心。

### 5.4 Banner 与正文衔接

不照搬 Firefly 的多层水波纹。

采用内容容器上移 24–32px 覆盖 Banner 底边的方式完成过渡。若后续保留水波纹，应作为可关闭的小型装饰而非默认核心视觉。

## 6. 首页主体

### 6.1 取消 Landing Page 式 Hero 结构

当前首页中的 Hero 大卡、个人大卡、五个快捷链接卡片和最新文章按钮区将重新组织。

Banner 不再负责解释“这是一个 Astro 博客”。Banner 只负责氛围与站点身份。

### 6.2 个人侧栏

右侧使用一张主要个人信息卡，整合：

- 头像。
- 昵称。
- 两到三行个人简介。
- 简单统计，如文章数、分类数。
- GitHub、碎碎念、归档等快捷入口。
- 分类或标签摘要。

第一版不引入大量 Firefly 小组件。站点统计、日历、最近评论等未来按实际需求增量加入。

桌面端可使用 `position: sticky`，参考 `top: 88px`；移动端关闭 sticky。

### 6.3 快捷入口

原首页的仓库主页、碎碎念、文章归档、精选文章等入口不删除，但不再各自占用一张大型卡片。

它们合并到侧栏快捷链接或轻量按钮列表中。

## 7. 文章列表与卡片

首页文章区域成为视觉主体。

### 7.1 基础结构

文章卡采用 Firefly 式横向信息卡：

- 左侧：标题、发布日期、阅读时间、摘要、标签。
- 有封面时：右侧放置约 28–32% 宽度的封面图。
- 无封面时：文字区完整占宽。

### 7.2 文章卡视觉

- 圆角：14–16px。
- 背景：接近实色。
- 边框：1px 极淡分隔线。
- 默认基本无大阴影。
- hover：最多约 -1px 轻微位移、边框或背景轻微变化。
- 不使用普通 hover 彩色 glow。
- 标题约 1.35–1.5rem。
- 摘要使用次级文字色。
- 标签使用 6–8px 圆角的小矩形浅底样式，而不是全部胶囊。
- 可保留一条很短的主题色竖线作为文章识别元素。

### 7.3 Section Header

“最新文章 / 查看全部”改成普通博客 section header。

- `最新文章` 约 1.25rem。
- 右侧使用文本链接 `全部文章 →`。
- 不再使用完整胶囊按钮承担“查看全部”。

## 8. Design Tokens

### 8.1 亮色模式

建议方向：

- 页面背景：接近 `#f6f6f8` 或轻暖灰。
- 卡片：接近纯白。
- 主文字：约 `#25252a`。
- 次级文字：约 `#6f7078`。
- 主题色：保留粉色身份，但降低使用面积和饱和度。
- 紫色和橙色仅保留为少量辅助色，不参与普通卡片和主按钮渐变。

具体色值在实现阶段结合现有视频与头像素材做一次视觉校准。

### 8.2 暗色模式

建议方向：

- 页面背景：约 `#15151a`。
- 卡片：约 `#1d1d23`。
- 不使用纯黑作为普通大面积背景。
- 分隔线仅比背景略亮。
- 主题粉色提高一点亮度保证可读性。

### 8.3 圆角

- 普通卡片：14–16px。
- 普通按钮：8–10px。
- 标签：6–8px。
- 头像、状态点等真正圆形元素使用 `9999px`。
- 减少通用 `border-radius: 999px`。

### 8.4 阴影

普通卡片默认无阴影或只保留类似：

`0 2px 10px rgba(0, 0, 0, 0.05–0.08)`

导航滚动后可以稍明显，但不出现彩色 glow。

### 8.5 按钮

- 主按钮使用纯主题色或淡主题色底。
- 不使用粉→紫渐变主按钮。
- 次按钮使用浅底、边框或文本样式。
- hover 仅改变背景、边框、文字色和最多 1px 位移。

### 8.6 字体

- 正文继续使用中文无衬线字体。
- 普通标题统一使用干净的 sans-serif。
- Banner 可保留较轻的个性化字体，但不得影响可读性。
- 不让强烈手写字体覆盖整个站点标题体系。

### 8.7 动画

普通页面动画主要控制在 150–250ms：

- 颜色变化。
- 透明度。
- 1px 左右轻位移。
- 简单展开/收起。

移除或弱化：

- 卡片大幅浮起。
- 持续漂浮装饰圆点。
- 持续呼吸发光。
- 普通交互中的过度 scale。

### 8.8 毛玻璃

普通页面只允许在以下场景使用：

- 滚动后的 navbar。
- 弹窗或浮层。
- 必要的临时控制面板。

文章卡、个人卡、归档卡等主内容组件使用接近实色背景。

沉浸页面不受这一限制。

## 9. 响应式策略

### 桌面端

- 约 50vh Banner。
- 双栏主内容。
- sticky 个人侧栏。
- 文章封面位于右侧。

### 平板端

- Banner 保持中等高度。
- 双栏可继续存在，但缩窄侧栏；空间不足时提前切单栏。
- 减少导航文字间距。

### 移动端

- Banner 约 34–38vh，目标 36vh。
- 单栏布局。
- 个人卡位于文章区前方，但压缩内容高度。
- 文章封面转为顶部横图或隐藏次要封面信息，避免拥挤。
- 不使用 sticky 侧栏。
- 导航转为现有可访问的移动菜单逻辑，视觉语言与桌面一致。

## 10. 保留功能与非目标

本次改造应保留：

- 视频背景及现有播放/循环恢复能力。
- 音乐播放器与 Project SEKAI 相关功能。
- 碎碎念。
- 文章内容与现有 Astro Content 数据。
- 搜索、主题切换等现有功能。
- 评论或其他已经存在的业务能力。

本次不做：

- 整站迁移到 Firefly 源码。
- 重做文章数据模型。
- 为了模仿 Firefly 引入其全部依赖、侧栏插件或布局系统。
- 第一版加入大量日历、站点统计、最近评论等组件。
- 改造沉浸页为普通 Banner 页。

## 11. 预期涉及区域

实现阶段预计重点检查并调整：

- `src/layouts/BaseLayout.astro`
- `src/pages/index.astro`
- `src/styles/global.css`
- 视频 Banner / `HeroSlideshow` 相关组件
- 导航相关组件或 BaseLayout 中的导航 DOM
- 首页个人资料与文章列表组件（可根据现状拆分）
- 普通文章列表/归档页面的共享卡片样式

若发现首页与其他页面样式耦合过深，可新增少量独立组件或样式文件，但不进行无关重构。

## 12. 验收标准

完成后应满足：

1. 首页首屏表现为约 50vh/36vh 视频 Banner，而不是全屏玻璃拟态 Landing Page。
2. 普通页面内容区拥有明确实色背景，与视频 Banner 分层。
3. 导航初始透明、滚动后轻玻璃化，不再是大型悬浮胶囊。
4. 首页主要内容为文章主栏 + 个人侧栏。
5. 原五个快捷卡片不再作为首页主要视觉块存在。
6. 文章卡片接近 Firefly 的内容优先横向结构，有封面时右图、无封面时全宽文字。
7. 普通卡片不再使用彩色 glow、多层 gradient 和高强度 blur。
8. 全站 `999px` 胶囊圆角只保留在真正需要的元素上。
9. 普通页面动画明显更克制，持续漂浮装饰被移除。
10. 沉浸页面继续保持全屏视频背景和原有体验。
11. 亮暗模式均具备足够的文字对比度和统一层级。
12. 移动端没有因为侧栏、Banner 或横向文章卡导致溢出与拥挤。
13. 现有博客业务功能、音乐/SEKAI 功能和文章内容不因视觉改造失效。

## 13. 后续实现策略

设计确认后再进入实施计划。实现应优先按以下顺序降低风险：

1. 建立新的普通页 design tokens。
2. 改导航和 Banner 布局。
3. 改首页主体双栏结构。
4. 改文章卡和侧栏。
5. 统一普通内容页视觉。
6. 做移动端适配。
7. 回归沉浸页、视频循环、音乐/SEKAI 功能。
8. 运行构建、现有测试和新增必要的结构测试。

实现期间不直接修改 `main`，继续使用独立 feature branch，完成验证后再由用户决定是否合并。
