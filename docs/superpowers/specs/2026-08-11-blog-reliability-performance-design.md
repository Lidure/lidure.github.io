# 博客可靠性与首屏性能优化设计

## 目标

在不改变现有粉紫暗色视觉、GitHub Pages 部署方式、动态背景和全站播放器功能的前提下，修复搜索、域名元数据和技术文章排版问题，并降低首次打开页面时的资源负担。

## 范围

本轮包含以下改动：

- 恢复 Fuse.js 文章搜索。
- 让 sitemap、RSS、canonical 和基础分享元数据使用 `https://lidure22.xyz`。
- 修复“视觉光流公式推导与文献支持”文章的重复一级标题和未渲染公式。
- 让背景先显示静态图片，页面完成首屏渲染后再加载视频。
- 压缩首页头像，生成尺寸合适的 favicon 与 Apple Touch Icon。
- 碎碎念、评论、表情互动继续向所有访客公开；仅站长发布、删除和管理密钥界面进入管理模式后显示。
- 增加构建后回归检查，覆盖本轮修复的关键输出。

本轮不迁移 MP3、不删除动态背景、不重做播放器、不调整整体配色和导航结构，也不改变 GitHub Pages 部署方式。

## 设计

### 搜索

文章元数据继续在 Astro 构建时由内容集合生成。页面使用 Astro 原生 HTML 注入能力输出一个 `application/json` 数据节点，并将可能结束脚本标签的 `<` 字符转义为 Unicode 序列。浏览器脚本读取该节点后初始化 Fuse.js。

当数据节点缺失或 JSON 无法解析时，搜索页显示明确的不可用提示，不再抛出未捕获异常。无关键词时保持结果区为空；有关键词时显示匹配数量或“没有找到”提示。

### 最终访问域名与元数据

Astro 的 `site` 设置为 `https://lidure22.xyz`。这只决定构建产物中的绝对地址，不改变 GitHub Pages 源站和 Cloudflare 转发关系。

基础布局输出 canonical、Open Graph 标题、描述、站点类型和分享图片地址。RSS 和 sitemap 由相同的 `site` 配置生成，避免同一站点同时暴露两套主域名。

### 技术文章排版

页面模板保留文章标题作为唯一 H1，Markdown 正文不再重复同名 H1。开头列表中的行内公式统一使用 remark-math 能识别的 `$...$` 定界符；独立公式继续使用 `$$...$$`。

### 首屏背景加载

默认背景列表的第一项改为静态图片。初始化时立即请求并显示该图片，不请求视频主体。

首屏完成后，通过 `requestIdleCallback` 启动视频准备；不支持该 API 时使用短延时回退。只有当前轮播即将进入视频项时才加载对应视频元数据，不在首屏阶段预热下一段视频。用户关闭背景或关闭自动轮播时，不进行后台视频准备。

视频加载或播放失败时继续保留当前静态背景，不出现空白背景，也不阻塞页面其他功能。

### 图片资源

首页头像生成 256×256 WebP，并保留明确的宽高属性。站点图标生成浏览器 favicon 和 180×180 Apple Touch Icon，不再让所有设备下载原始 1 MB 图片。

原始图片暂时保留，避免影响其他潜在引用；页面入口全部改用优化版本。

### 碎碎念权限界面

普通访问 `/moments/` 时可以查看全部动态、评论和表情互动。站长发布按钮、发布表单和删除按钮在初始 HTML 中默认隐藏，避免静态站点因查询参数无法生成两套页面。

访问 `/moments/?admin=1` 时显示上述管理界面。所有写操作仍必须携带现有管理密钥，查询参数只控制界面显示，不授予权限。API 继续作为最终权限边界。

### 测试与发布

新增 Node 构建产物测试，在 `astro build` 后验证：

- 搜索页包含可解析的文章数据且不残留对浏览器端 `jsonData` 变量的引用。
- sitemap 使用 `lidure22.xyz`。
- 目标文章只有一个 H1，且开头不残留未处理的 `\\frac` 文本。
- 首页使用优化头像和图标。
- 默认背景首项为静态图片，视频延迟准备逻辑存在。
- 碎碎念管理控件默认隐藏，管理查询参数的客户端逻辑可以启用控件。

完成后运行类型检查、正式构建、构建产物测试，并在桌面宽度和窄屏宽度下检查首页、搜索页、文章页及碎碎念页面。代码提交到 `agent/fix-blog-speed` 分支并创建 Draft PR，合并后仍由现有 GitHub Actions 发布到 GitHub Pages。

## 风险控制

- 若浏览器不支持空闲回调，使用定时器回退，不影响背景显示。
- 管理查询参数不包含密钥，也不绕过服务端鉴权。
- 图片优化只替换页面引用，不删除原始资产。
- 不在本轮修改音乐资源路径，避免播放器回归范围扩大。
