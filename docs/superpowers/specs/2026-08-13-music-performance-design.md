# QQ 音乐统一接口与页面性能优化设计

## 目标

改善 QQ 音乐歌单导入后的可播放率，并降低首页首次加载、导航切换和背景动画造成的卡顿。保持现有 Astro + GitHub Pages + Cloudflare 架构，不把 Cookie 或密钥提交到仓库。

## 方案

### 1. 音乐接口

前端播放器使用统一的音乐服务接口获取歌单和播放地址。接口响应统一为歌曲元数据、封面、歌词（可选）和播放 URL（可选）。前端不再自行拼接或批量调用 QQ `vkey` 接口。

接口边界：

- `GET /playlist?server=qq&id=<playlist-id>`：返回歌曲列表。
- `GET /url?server=qq&id=<song-id>`：按需获取单首播放地址。
- Cookie 只通过用户浏览器请求传递给接口，不写入日志、不进入构建产物。
- 无播放地址的歌曲保留在列表中，并显示“暂不可播放”，不伪装成可播放歌曲。
- 播放地址按需获取并短时间缓存，避免导入 165 首歌曲时同时请求 165 个地址。

前端导入流程：先显示歌单元数据；用户点击某首歌时再请求该歌曲播放地址；成功后交给 `<audio>` 播放，失败则显示明确原因并允许重试。

### 2. 性能优化

- SEKAI 播放器保留界面，但延迟到用户首次点击播放器按钮后初始化重型目录、音频分析器和远程数据。
- 背景视频只保留当前播放元素，取消首屏不必要的下一个视频预加载；图片背景优先展示。
- 粒子定时器只在开关开启时运行，导航和页面隐藏时清理动画帧与定时器。
- 全局脚本使用一次性生命周期绑定，页面切换只更新当前 DOM，不重复创建播放器、音频上下文和事件监听器。
- 非关键图片使用懒加载并保留明确尺寸；字体不阻塞首屏绘制。
- 保持页面过渡效果，但缩短不必要的过渡等待，避免导航时等待视频或远程数据。

## 错误处理

- 音乐接口失败：显示“歌单加载失败”，保留重试按钮。
- 单曲地址失败：显示“暂无可用播放地址”或“登录状态已失效，请更新 Cookie”。
- Cookie 缺失或格式不完整：在 QQ 音乐设置区域提示完整 Cookie 要求，不展示 Cookie 内容。
- 背景视频失败：自动回退到静态图片或渐变背景，不阻塞页面。
- 所有远程请求设置超时和取消机制，导航离开后取消未完成请求。

## 验收标准

- QQ 歌单导入不再一次性批量请求全部播放地址。
- 歌曲列表能区分“已取得地址”和“暂不可播放”。
- 点击可播放歌曲可以正常播放；失败歌曲有明确提示和重试入口。
- 首次打开页面不初始化完整播放器目录和音频可视化。
- 导航切换后时钟、访问量、背景和播放器不重复初始化或明显卡顿。
- `npm run check`、`npm run build` 和针对音乐/性能生命周期的回归检查通过。
- 不新增提交的真实 Cookie、密钥或第三方服务凭据。

## 范围控制

本次不承诺绕过 QQ 音乐会员、地区或版权限制；统一接口只改善授权传递、按需请求、缓存和错误提示。若第三方接口本身无法返回播放地址，页面会如实显示不可播放。
